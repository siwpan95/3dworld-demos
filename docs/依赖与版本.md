# 依赖与版本（3dworld-demos）

> 最后更新：2026-10-22 ｜ 适用范围：本仓（演示集）与引擎仓 `siwpan/3dworld` 的**仓间关系**

## 1. 一句话结论

**演示不再自己找引擎，引擎由 pip 提供。**

```
pip install -r requirements.txt      # → 3dworld（含 pyglet 等传递依赖）+ 可选 zhuangtaiji
python examples\<名字>.py
```

`examples/*.py` 里**不再有任何 `sys.path` 引导**，第一行 concerns 只有一句：

```python
from world3d.platform.app import DemoApp, run
```

## 2. 为什么改（旧做法已经失效）

演示仓 2026-10-19 从引擎仓剥离之前，每个 demo 顶部都写着：

```python
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
```

当时 `examples/` 在引擎仓内部，上一级目录就是引擎根，所以这句能把 `world3d/` 推到
搜索路径上。**剥离后这句指向的是演示仓自己的父目录**（本机是 `D:\projects`），
里面根本没有 `world3d/` —— 于是 39 个 demo 全部 `ModuleNotFoundError`。

| 项 | 改之前 | 改之后 |
|---|---|---|
| 引擎来源 | 相邻源码目录 + `sys.path` 引导 | `pip install 3dworld`（PyPI 发行版 0.4.1） |
| 引导行数 | 42 个文件里共 201+34 行 | 0（`mountain.py` 保留 1 行，见 §5） |
| 根定位 | 各自算 `ROOT = dirname(dirname(__file__))` | 统一用引擎导出的 `PROJECT_ROOT` |
| `zhuangtaiji` | 环境变量 + 目录探测 `G:\repos\zhuangtaiji`（磁盘已不存在） | `pip install zhuangtaiji`，装了就启用 |

## 3. 三份清单各自的分工

| 文件 | 用途 | 何时用 |
|------|------|--------|
| `requirements.txt` | 运行依赖，**接受小版本浮动**（`3dworld>=0.7.6,<0.8`） | 日常跑演示 |
| `requirements.lock.txt` | 精确锁版快照（2026-11-14 基线；2026-11-22 仅把引擎同步到 0.7.6，其余依赖不动） | 截图对照 / 发版归档 / CI 复现 |
| `requirements-dev.txt` | 门禁（ruff）与打包（PyInstaller） | 改代码 / 打 exe / 录成片时 |

> 演示**不锁引擎小版本**：它们是能力的演示形态，引擎发新版就跟着涨。
> 要逐位可复现时才用 `.lock.txt`。

### 传递依赖不用自己列

`3dworld` 自己声明了 `pyglet==2.1.16` / `PyYAML>=6` / `watchdog>=4`（后两者是
vendored cordis 的硬依赖），pip 会自动带上，`requirements.txt` 里**故意不重复列**，
避免两份清单漂移（引擎仓 `requirements.txt` 已经是"转发 pyproject"的单一事实来源）。

### ⚠️ numpy：历史例外已收编，清单仍保留兜底（2026-10-26 实测 → 2026-11-14 复核）

0.4.1 时代 `3dworld` **没有声明 numpy**，但 `world3d.physics.*` / `anim.*` /
`engine.terrain_lod` / `engine.terrain_clipmap` 都 `import numpy`。干净 venv 里
`pip install 3dworld` 之后 `from world3d.physics.jolt_lite import World` 直接
ModuleNotFoundError，所以本仓 `requirements.txt` 显式列出 numpy。
引擎 **0.7.0 起已把 `numpy>=2.0` 收进 `install_requires`**：0.7.3 干净 venv 实测
只装 wheel 即带 numpy，11 个子包（含 `physics/jolt_lite`、`anim/ozz_lite`、
新增的 `engine/spectrum`）全部可 import。这一行现在只是对旧环境的兜底，
不再是引擎的依赖漏洞。

### ⚠️ 版本上限曾经把引擎锁死在 0.3.0

`3dworld>=0.3.0,<0.4` 这个上限让 pip 只能拿到 0.3.x：而 0.3.x 的 wheel **没有**
`world3d/physics`、`anim`、`engine/terrain_lod`、`engine/terrain_clipmap`，于是
依赖这些模块的演示一律"引擎没发布这个能力"。实测 0.4.1 的 wheel 全部带齐，
2026-10-26 把上下限一并抬到 `>=0.4.1,<0.5`。

### 可选增强：zhuangtaiji

只有 `examples/scene_walker.py` 用（`try: import` + `except ImportError: 降级`），
驱动马尔可夫发光变体。装了会在状态栏看到 `[mc] ember -> spark`，没装则静默跳过。

## 4. 两个必须的环境变量

pip 安装的引擎推导不出**演示仓**在哪，而 `--shot` 截图落点、cordis 配置树都在本仓：

```bat
env.bat                              :: 一键设置（推荐）
:: 等价于手工：
set WORLD3D_PROJECT_ROOT=%CD%        :: 截图写 docs/、场景 JSON 从这里找
set WORLD3D_CONFIGS=%CD%\configs     :: cordis 配置树（host.tree 用）
```

不设的后果：截图会落到 `site-packages/../docs`（通常不存在或直接报错），
`boxward/brickward/swarmward/tower_defense/godhand` 这类挂载 cordis 玩法内核的 demo
找不到配置文件。

## 5. 例外：`mountain.py` 仍有一句 `sys.path.insert`

它 `from terrain_flyover import _hash01, _value_noise, _fbm` —— 依赖的是 `examples/`
**内部的兄弟模块**，不是引擎。这是演示之间的代码复用（同一套可复现哈希），
与"引擎由 pip 提供"不冲突，故保留并在注释里写明。

## 7. 常见问题

**Q：`import world3d` 报 `ModuleNotFoundError`？**
A：没装引擎，或装到了别的解释器。确认 `python -m pip install -r requirements.txt`
用的就是跑 demo 的那个 python（`where python` / `python -m pip -V`）。

**Q：能同时用本地引擎源码调试吗？**
A：可以 `python -m pip install -e ..\3dworld`（引擎仓目录），导入名依旧是 `world3d`，
本仓代码不需要任何改动 —— 这正是"由 pip 提供"的好处：源码版与发行版对演示完全等价。

**Q：demo 里的 `PROJECT_ROOT` 是什么？**
A：引擎 `world3d.platform.app` 导出的常量，取值优先环境变量 `WORLD3D_PROJECT_ROOT`，
未设时才按引擎包位置推导。原来各 demo 自己算的 `ROOT` 已全部换成它。
